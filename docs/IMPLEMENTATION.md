- 대표 전화 및 이메일 2개 반영. 전화 링크는 국제 형식, 이메일은 각각 별도 링크로 연결.

예약·연락처 반영 후에는 모든 페이지의 예약 링크가 설정된 실제 URL과 일치하고 함께 활성화되는지도 산출물 검사에 추가했습니다. 홈·위치·문의 화면에서 밝은/어두운 모드와 375/1440px 표시, 국제 전화 링크와 이메일별 링크를 확인했습니다. 출시 점검의 누락 항목은 현재 실사진 5종입니다.

Lighthouse 수치는 실제 호텔 사진이 없는 초기 버전의 로컬 측정입니다. 실사진 등록과 실제 HTTPS 배포 후 다시 측정해야 합니다. 자동 접근성 검사는 수동 검수를 대체하지 않습니다.

소스는 `codex/nouver-initial-site` 브랜치와 [초안 PR #1](https://github.com/resumet/nouvelle-homepage/pull/1)에 올렸습니다. 초기 소스 47개 파일의 Git 해시가 로컬과 원격에서 일치함을 확인했고, [GitHub Actions 최초 빌드](https://github.com/resumet/nouvelle-homepage/actions/runs/40634901752)는 성공했습니다. GitHub Pages 공개 배포와 PR 병합은 수행하지 않았습니다.

## 출시 전 필요한 자료

1. 사용 권한이 확인된 외관/히어로, 디럭스, 스위트, 스피커, 지하 욕장 실사진.
2. 스피커 설치 객실·제품 정보, 객실 정원·침대 구성, 체크인·체크아웃, 주차·아동 정책의 확인된 안내.
3. 지하 욕장 요금·예약·회차·투숙객 이용 조건의 확인된 안내.
4. 호텔의 공식 로고가 있다면 현재의 문자형 워드마크 교체.
5. 정책 문구의 운영 주체 검수, 공식 도메인·실제 공개 언어 범위 확정.

실사진 자리는 명확하게 표시했습니다. 후기, 평점, 미확인 시설·서비스·무료 혜택은 만들지 않았습니다. 스위트 객실 내 욕탕과 지하 욕장은 구분했습니다.

## 이어서 작업하는 방법

`README.md`의 실행·자료 등록·GitHub Pages 절차를 따르세요. 사진 데이터는 `public/`을 제외한 상대 경로, 설명, 실제 이미지 크기를 함께 입력합니다. `npm run release:check`를 통과하고 내용 검수가 끝나면 저장소의 `PUBLISH_SITE=true` 변수로 공개 배포를 활성화할 수 있습니다.

성능 보고서는 `npm run preview` 실행 중 별도 터미널에서 `npm run audit:mobile`, `npm run audit:summary`로 다시 생성합니다. Chrome 자동 탐색이 안 되면 `CHROME_PATH`를 지정하세요. 보고서와 스크린샷은 추적 제외된 `artifacts/`에 보관합니다.

구현 참고: [Astro GitHub Pages 배포 안내](https://docs.astro.build/en/guides/deploy/github/), [Tailwind Astro 설치 안내](https://tailwindcss.com/docs/installation/framework-guides/astro).
